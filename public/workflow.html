⚡ Section 2 — Vendor Selection: Full Logic

computeVendorComparisons()

Every eligible vendor for a product is scored on a composite 0–100 scale across four weighted dimensions. The vendor with the lowest landed cost wins first; composite score is the tie-breaker.

💰 Price Score
40%
(1 − (landedCost − minLandedCost)
÷ minLandedCost) × 40
The cheapest vendor gets the full 40 pts. Every other vendor is penalised proportionally to how much more expensive they are. A vendor 2× the min price scores 0 on this dimension.
⭐ Rating Score
30%
(vendor.rating ÷ maxRating) × 30
Vendor rating (e.g. 1–5 stars or 1–100). The highest-rated vendor in the comparison pool gets the full 30 pts. All others are scaled proportionally.
⏱ Lead Time Score
15%
(1 − (leadTime − minLeadTime)
÷ (maxLeadTime − minLeadTime)) × 15
Shorter delivery lead time = more points. The fastest vendor scores 15 pts; the slowest scores 0. Range-normalised so it adapts to the actual spread in the comparison pool.
📦 Stock Score
15%
(vendor.availableStock ÷ maxStock) × 15
The vendor with the most available stock gets 15 pts. Ensures the system favours vendors who can fulfil the full order without risk of a short-ship.

Landed Cost Formula

ComponentFormula / SourceNotes
Base Price vendor.price per unit Raw unit price as listed by the vendor in their catalog
Logistics % vendor.logisticsPct Percentage added for freight/transport costs
Handling % vendor.handlingPct Packaging, warehousing, and last-mile handling charges
Extra Charges % vendor.extraChargesPct Any other surcharges declared by the vendor
Tax % taxEngine.getRate(category) GST rate resolved from product category — included in landed cost for scoring, but shown separately in the PO
Landed Cost / Unit BasePrice × (1 + logistics% + handling% + extra%) × (1 + Tax%) This is the primary sort key — lowest wins

All Conditions Checked During Vendor Selection

ConditionCheckOutcome if FAILS
Has the product vendor.products.includes(productId) Vendor excluded entirely from comparison
Has available stock availableStock = physicalStock − reservedStock > 0 Vendor excluded (cannot fulfil any qty)
Sufficient stock for qty availableStock >= requestedQty Vendor stays in pool but gets lower Stock Score (15%) — may still win on price; admin sees the shortfall
Price data present vendor.price > 0 Vendor excluded (cannot compute landed cost)
Rating data present vendor.rating >= 0 Rating defaults to 0 — vendor scores 0 on the 30% dimension
Lead time data present vendor.leadTimeDays >= 0 Lead time defaults to max in pool — vendor scores 0 on the 15% dimension
Minimum 2 vendors eligibleVendors.length >= 2 Scoring still runs with 1 vendor; that vendor auto-wins with full score
Min landed cost > 0 minLandedCost > 0 Price score normalisation is skipped to avoid division by zero; all vendors score 0 on price
Lead time range > 0 maxLeadTime − minLeadTime > 0 All vendors tied on lead time — all score 15/15 on that dimension
Global category markup categoryRules[category].markup exists Extra markup (margin + buffer) added to landed cost for scoring only — does NOT change vendor's base score directly

Ranking Logic — How the Winner is Picked

Automatic (Price Engine Default)

1
Exclude any vendor that fails a hard condition (no product, no stock, no price)
2
Calculate Landed Cost per unit for each remaining vendor
3
Score each vendor across all four dimensions (Price 40, Rating 30, Lead 15, Stock 15)
4
Sort primary: lowest landedCostPerUnit first
5
Sort secondary (tie-break): highest composite score first
6
Winner = index [0] of the sorted list — auto-assigned to this line item
// Simplified sort logic
vendors.sort((a, b) => {
  if (a.landedCost !== b.landedCost)
    return a.landedCost - b.landedCost; // cheapest first
  return b.score - a.score; // highest score wins tie
});

Stock Allocation — Cheapest-First Fill

1
allocateQtyAcrossVendors() runs if a single vendor can't supply the full quantity
2
Vendors sorted cheapest-first (same order as winner selection)
3
Drain cheapest vendor first — take as much as their available stock allows
4
Spill remaining qty into the next cheapest vendor, then the next, until fulfilled
5
Each vendor's allocation stored in vendorAllocations[] on the order
6
If total available stock across all vendors < requested qty — order is flagged as partially fulfillable

Selling Price Margin — Resolution Hierarchy

PriorityRuleScope
1st (highest) Product-specific profit % Set per individual product — overrides everything
2nd Category-specific profit % per client Set at category level for a specific client — overrides global default
3rd (fallback) Global client default profit % Applied when no product or category rule matches for this client
Global overlay Category markup (margin + buffer) Applied on top of landed cost for scoring calculations only — does not change vendor base score

Admin Override — Vendor Selection Modal Rules

🔧
What Admin Can Do
Vendor Selection Modal — OrderDetailsPage
  • View all eligible vendors with their ranked scores, landed cost, stock, lead time, and rating
  • Check/uncheck any vendor to include or exclude them from the PO
  • Manually edit the qty allocated to each vendor (split-sourcing across multiple vendors)
  • See real-time total allocated vs required qty — must match exactly
  • Override the system default to prefer a vendor based on relationship or quality reasons
⚠️
Validation Rules (Cannot Proceed Until Met)
Hard gates before Confirm button enables
  • At least 1 vendor must be selected
  • Total allocated qty across all selected vendors must exactly equal the sub-order qty
    totalAllocated === sub.qty
  • Each selected vendor must have a qty > 0 assigned
  • Any vendor with insufficient stock for their allocated qty shows a warning — admin must acknowledge
🔄
What Happens After Override
System reconciliation on confirm
  • Stock reservations are re-run for the new vendor allocation
  • Old reservations from the auto-assigned vendor are released
  • New vendorAllocations[] written to the order record
  • On PO raise, physical deduction hits the overridden vendor, not the original auto-assigned one
  • Reserved stock release remains greedy (most-reserved first) across all vendors regardless of which vendor was chosen
