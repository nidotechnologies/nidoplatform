# NIDO – Centralized Approval Workflow Engine

## Objective

Upgrade the **existing Configuration Hub → Approval Workflow** tab into the single centralized approval workflow management system for the entire NIDO platform.

Do NOT create a separate Approval Workflow module.

Do NOT create duplicate approval settings inside Clients, Vendors, Orders, Procurement, Finance, Catalogue, Stock, Contracts, or other modules.

The existing:

**Configuration Hub → Approval Workflow**

must become the single source of truth for defining, maintaining, executing, tracking, and auditing approval workflows across NIDO.

The approval engine must work LIVE with the existing application, database, authentication, RBAC, notifications, and platform workflows.

# 9. Approval Mode

Support:

### Sequential

Level 2 starts only after Level 1 approves.

### Parallel

All configured approvers receive the request simultaneously.

### Any One

Any one eligible approver can approve.

### All Required

Every assigned approver must approve.

### Majority

Approval succeeds when the configured majority approves.

Implement only modes that are technically compatible with the existing architecture, but structure the database so additional modes can be added later.

# 30. Final Acceptance Criteria

The implementation is complete only when:

* Configuration Hub → Approval Workflow is fully functional.
* Admin can create workflows.
* Admin can edit workflows.
* Admin can configure conditions.
* Admin can configure multiple approval levels.
* Admin can assign existing NIDO roles/users.
* Admin can activate/deactivate workflows.
* Workflow versions are maintained.
* Approval requests are generated automatically.
* Approvers can approve/reject/send back.
* Notifications are triggered.
* SLA/escalation works where configured.
* Approval history is maintained.
* Audit trail is maintained.
* Originating transactions update automatically.
* Existing NIDO RBAC controls access.
* All data persists in the real database.
* Existing modules use the centralized approval engine.
* No duplicate approval configuration is introduced.
* Existing NIDO functionality continues to work.

After implementation, run a complete audit of the repository and report:

1. Files changed
2. Database changes
3. Existing functionality reused
4. New approval functionality
5. Modules integrated
6. Any remaining approval-related hardcoded logic
7. Any errors
8. Test results

Do not consider the task complete until the approval workflow has been tested end-to-end using an actual NIDO transaction.
