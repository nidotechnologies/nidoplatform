Build a complete enterprise RBAC (Role-Based Access Control) system for the NIDO platform.

IMPORTANT:
The RBAC system must be fully configurable from the NIDO platform UI in the future. Do NOT hard-code role permissions into frontend components or backend route files.

The administrator must be able to add, edit, remove, activate/deactivate, and change:
- Roles
- Modules
- Module groups
- Permission actions
- Role-module permissions
- Permission assignments

Any change made through the admin UI must immediately affect authorization throughout the application.

3. PERMISSION ACTIONS
==================================================

Every role-module relationship can contain these permissions:

1. View
2. Create
3. Edit
4. Delete
5. Approve
6. Export
7. Import
8. Manage
9. Configure

Do NOT assume that every module needs every permission.

Each role/module combination must independently support enabling/disabling each permission.

Example:

Procurement Lead → Vendor Quotations

View = true
Create = true
Edit = true
Delete = false
Approve = true
Export = true
Import = true
Manage = true
Configure = false

4. IMPORTANT — NO DATA SCOPE
==================================================

Do NOT include the following in this RBAC implementation:

- All
- Department
- Team
- Assigned
- Own
- No Access

The current RBAC design is ONLY:

Role → Module Group → Module → Permission Actions

There should be NO Scope column in the permission matrix.

==================================================
16. SECURITY
==================================================

Authorization must be enforced on the backend.

Do NOT rely only on hiding UI buttons.

Every protected API endpoint must check:

1. Authenticated user
2. User's active role
3. Module permission
4. Requested action

Example:

User:
Praveen

Role:
Procurement Analyst

Request:
DELETE /api/vendor-quotations/123

System checks:

Does Procurement Analyst have Vendor Quotations → Delete?

If false:

Return HTTP 403.

Frontend should also hide/disable the Delete button, but backend authorization is mandatory.

18. MENU VISIBILITY
==================================================

Navigation should automatically respond to permissions.

If user has:

Vendor Quotations → View

Show Vendor Quotations menu.

If user has no permissions for Vendor Quotations:

Hide Vendor Quotations from navigation.

If user has View but not Edit:

Show the module but hide/disable Edit actions.

If user has View + Create:

Show Create button.

If user has Approve:

Show Approve action.

Show configuration controls.
